# 小さなテスト例（`tests/cases/`）

`examples/` の大きな作例とは別に、**短い例を観点ごとに1つずつ**置く。どの例も機器は2〜8個（段への折り返しを試す例だけが多め）で、1つの例では1つのこと（1つの機器・ポート・パラメータの値・JSON のキー・ポートの向きの組み合わせ）だけを試す。どれも配置・配線は 0.1 秒ほどで終わり、`pytest tests/test_cases.py` 全体でも数秒。

## フォルダ

| フォルダ | 何を試すか |
|---|---|
| `routing/flow/`, `routing/order/` | 配管の向きの総当たり。横型ドラム2基 A→B を、出口ポートの向き（東西南北）× 入口ポートの向き（東西南北）× 段の関係（同じ段 `same`／B が上 `up`／B が下 `down`）の 48 通り。`flow` と `order` の両方のレイアウトで。名前は `<出口>_to_<入口>_<段>`（例: `n_to_s_up`） |
| `elements/` | 標準エレメントそれぞれと、パラメータの値ごと（弁の `kind` 7種と縦置き、ドラム・塔・熱交換器・フィルター・撹拌槽（ジャケット付き）・貯槽・空冷器（ファン台数）・加熱炉の寸法と充填層、ヘッダーの枝数・間隔・枝管機器の書き方3通り、tee の腕の組み合わせ、計器の `field`/`dcs`、ユーティリティの丸の `point` 4方向） |
| `ports/` | 各エレメントのポートの系列すべて（`top`/`bottom`、鏡板の `n<i>`/`s<i>`、胴の `w<i>`/`e<i>` と `_low`/`_mid`/`_high`（槽・塔・撹拌槽・貯槽）、プレート式熱交換器の2流体、熱交換器の胴側の逆流ポート、フィルターの `vent`/`drain`、ヘッダーの `main_e`/`m<i>`、計器の四方） |
| `transform/` | `rotation`（0/90/180/270）× `mirror`。ポンプは8通りすべて、熱交換器・横型ドラム・弁・塔はいくつか |
| `lines/` | 線種（`pipe`/`utility`/`signal`/`instrument`、独自の線種、既定の線種の上書き）、インライン機器（文字列・辞書、`id`/`params`/`level`/`elevation`/`desc`/`in`/`out`、複数、右から左、後で宣言される id への接続）、`anchor`（`auto`/`src`/`dst`）、リサイクル（明示・自動検出・インライン弁付き） |
| `layout/` | `layout`（省略/`flow`/`order`、`order` で逆順）、`version`、`level`（省略・一部だけ・ポンプを上げる）、`elevation`、`span`、`desc`、追加ポート `ports`、段への折り返し（`rows` の `auto`/`single`、予熱列、段をまたぐ調節計、予熱器のユーティリティのフラグ、`span` の機器） |
| `topology/` | 配管のつながり方（直列、分岐・合流 2本と3本、分かれて合流、ノズルごとの枝、並列系列、ループ、還流、サイドストリッパー、右から左、ドラムの下のポンプ、交差、つながっていない2系統、機器の迂回） |
| `flags/` | 図面端のフラグ（左端・右端、左向き、`edge` の指定、`local` の `true`/`false`/`auto` と `order` での `local`、左右に積む、2行の文字、長さ、文字なし、2本が1つのフラグへ、上の段のフラグ） |
| `custom/` | `custom_elements`（図形 `rect`/`polyline`/`ellipse`/`arc`、`boundary`/`fill`/`pipe`/`closed`、`label_pos` 5種、`nozzles`、`texts`、寸法とポート、インライン、回転、ヘッダーの枝管に載せる） |
| `revisions/` | 改訂（`revisions`）: 予備ポンプの追加（使用中のポートへの分岐、インラインの逆止弁）、配管の撤去（共有する主管は残る）、名前付きインライン機器の撤去（配管をつなぎ直す）、機器の撤去（配管・フラグも消える）、2回の改訂（場所が足りず図を平行移動、後の改訂が前の改訂の配管を撤去）、置き換え（撤去したポンプの場所に新しいポンプを置く、2回続けて）、同じ id での取替、変更（その場で弁の種類と仕様を変える、タンクを背の高い塔にして元の場所で大きくする）、凍結（`frozen`。R1 まで凍結した図に R2 を描く） |
| `invalid/` | 受け付けない入力。チェックごとに1つ（未知のキー・型・ポート・線種、範囲外の値、重複 id など） |

## テスト（`tests/test_cases.py`）

- **スナップショット**: 正しい例はすべて、配置・配線・警告・描画が `tests/snapshots/cases/` と一致する
- **無駄な U ターンなし**: 警告（何もないところでの U ターン）が出ない
- **書き順に依らない**: `flow` の例は `elements` と `connections` を逆順にしても同じ図になる
- **JSON の往復**: `from_dict` → `to_dict` で、書いた内容がそのまま戻る（既定値は省かれる）
- **不正な入力**: `invalid/` の例はそれぞれ決まったエラーとメッセージで止まる（`INVALID` の表）
- **網羅チェック**（`test_cases_cover_every_option`）: 例全体で、次のすべてが少なくとも1回使われている。足りないと、足りない観点の名前を並べて失敗する
  - 標準エレメントの種類すべてと、それぞれのポートの系列すべて（`e12` → `e#` のように番号はまとめる）
  - 列挙パラメータの値すべて（弁の `kind`・`orientation`、熱交換器の `orientation`、計器の `mount`、フラグの `point`・`edge`・`local`）と、ほかのパラメータ（`PARAMS` の表）
  - `rotation` の4値と `mirror`、tee の4つの腕、ヘッダーの枝管機器の3つの書き方
  - JSON のキーすべて（トップ・機器・接続・インライン機器・線種・独自エレメント・改訂）と、改訂の撤去の書き方2通り（id と `{"from", "to"}`）、`layout`/`rows`/`anchor` の値すべて、線種すべて
  - 独自エレメントの図形の種類・キー・`label_pos`・ポートの4方向
  - 配管の向きの総当たり: レイアウト2種 × 出口4方向 × 入口4方向 × 段の関係3種（回転・反転後の向きで数える）

  必須の一覧の多くはコードから取る（`DEFAULT_LIBRARY` のエレメントとポート、`_ELEMENT_KEYS` などのキー、`LAYOUTS`・`ANCHORS`・`ROTATIONS`・`LABEL_POSITIONS`、`LineStyle` のフィールド）。エレメント・ポート・キー・選択肢を増やすと、それを使う例を足すまでこのテストが失敗する。エレメントのパラメータ名だけは表（`ENUMS`・`PARAMS`）に書く。新しいエレメントは `PARAMS` に載せないと `test_every_element_type_has_its_parameters_listed` が失敗する
- **振る舞い**（`test_cases_show_every_behaviour`）: 段への折り返し、自動主管、配管の交差、機器を迂回する配管、上下に重なる機器が、どれかの例で実際に起きる

## 見つかった不具合の扱い

例で不具合が見つかり、すぐには直さないときは、`test_cases.py` の `NO_ROUTE`（配線できない）か `NEEDLESS_UTURN`（無駄な U ターンの警告が出る）に例の名前と内容を書く。strict な xfail になるので、テストは通ったまま、直るとそのテストが失敗して知らせる。直したら表から外す。

これまでに見つけて直したもの:

| 例 | 内容 |
|---|---|
| `topology/merge_3` | 図面端のフラグ3本から1つのノズルへ合流すると、切り込み点がフラグの積み順に並んで主管が一直線にならず、配線できなかった（`RoutingError`）。フラグからの配管を並列系列とみなさないようにした。同じ原因の `split_2`・`split_3` も交差が減った |
| `transform/pump_r180` | 180° 回したポンプ（吐出が下向き）から上の段のフラグへの線が「何もないところでの U ターン」と警告されていた。ポートの向きと段で避けられない U ターンなので、警告しないようにした |
| `topology/split_3` | ポンプの吐出から3本に分岐して右端のフラグへ送ると、主管の切り込み点から下りる配管が交差した。右端のフラグを「近い機器ほど下」に積んでいたが、上から下りてくる配管では逆になる。下向きのポートへの配管のフラグは遠いものほど下に積むようにした（`flags/stack_left_into_bottoms` は左端で同じことを確かめる） |
| `flags/level_above` ほか4例 | 共通のフラグから並列のポンプ2台へ分配すると、手前のポンプ用の切り込み点が奥のポンプ（主管がまっすぐ入る端の機器）の前に置かれ、手前のポンプへの配管が U ターンして交差していた。切り込み点の位置は枝の腕（上下）につながる機器だけで決めるようにした。同じ原因の `topology/parallel_two`・`parallel_three_pumps`・`split_and_merge` も U ターンがなくなった |
| `topology/feed_main_two_columns` | ポンプから2基の塔の側面へ送ると、手前の塔は主管の上に持ち上がるのに、切り込み点の腕が下向きで、U ターンしていた。主管が下を通る容器のノズルへは腕を上向きにした（折れ 8→2、U ターン 2→0） |
| `routing/flow/n_to_s_up` ほか10例 | ノズルどうしを1セルでまっすぐつなぐと、両端のフランジの印と矢印が重なっていた。直結するノズルどうしは2セル以上離すようにした（横は隙間を2セル、上下に重なるときは段の間を広げる）。当時の作例でも、直列の熱交換器などで起きていた |

## 例の足し方

1. 該当するフォルダに `<名前>.json` を置く（機器は少なく、試すことは1つ。段は書いておくと速く、結果も変わりにくい）
2. `pytest tests/test_cases.py` を実行すると、初回はスナップショットが書かれる（skip と表示される）。もう一度実行して通ることを確かめる
3. 図を見るときは `pfd tests/cases/<フォルダ>/<名前>.json -o out.png`

不正な入力の例は `invalid/` に置き、`test_cases.py` の `INVALID` に例外の型とメッセージの一部を書く。

レイアウト・配線・描画を意図して変えたときは、スナップショットを書き直す: `PFD_UPDATE_SNAPSHOTS=1 pytest tests/test_cases.py`
