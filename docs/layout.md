# 自動配置・配線の決まり

[README](../README.md) の「自動配置のしくみ」の詳細。`flow` レイアウト（JSON の既定）で、機器の並び・段・配管の形がどう決まるかを書く。

## 流れからの自動配置（`"layout": "flow"`、JSON の既定）

各機器の**種類と接続（向き付き）だけ**を書けば、左右の並びは流れの向きから、高さ（`level`）は配管がいちばんすっきりするように自動で決まる。並び順・段・座標の指定は不要。

- JSON は `layout` を書かなければ `flow`。書いた順に並べたいときだけ `"layout": "order"` と書く（Python API の `Flowsheet()` は従来どおり `order` が既定。`to_dict` / `to_json` は `layout` を必ず書き出す）
- **`elements` と `connections` の書き順は結果に影響しない**。どちらの配列をどう並べ替えても、配置・配線・警告はまったく同じになる（`tests/test_order_free.py`）。内部では機器を id の自然順（`P-2` の次に `P-10`）、配管を両端の id 順に並べてから処理するので、流れから決まらない同点（同じ構成の並列系列の左右など）は id の順になる
- 配管の配線は流れの下流側の配管から順に探索する（書いた順ではない）
- 1つの機器から分かれる枝は、主流（いちばん長い流れ。同じ長さなら低いノズルから出るもの＝塔の缶出し）を最後に、ほかは容器のノズルの低い順に並ぶ（塔ならサイドドローが下から順、オーバーヘッド系は主流の手前）。各枝の配管は手前の枝の立ち下がりの上を通るので、交差しない。同じ構成の枝ばかり（並列系列）なら主流は決めず、id の順
- 配管は、ほかのポートの直前のセル（ノズルの出口）で曲がったり、そのポートの向きに沿って通り抜けたりしない（横切るのはよい）。先に引いた配管がノズルの出口をふさいで、そのノズルの配管が引けなくなるのを防ぐ
- 狭める探索（隙間を1つずつ詰める）は、まず下限まで一気に詰め、だめなら二分探索する
- 接続先の機器にしか配管が出ていない機器（塔へ入るスチームの丸など）は、左に寄せず、つながる機器のすぐ手前に置く
- 同じ高さで図面端に積まれるフラグは、配管が入れ子になって交差しないように並ぶ。機器へ下から届く配管（ポンプの吐出、側面のノズル）は、近い機器から来るものほど下のフラグ。機器の下向きのポート（上にある主管の切り込み点、容器の底）へ上がっていく配管は、そのフラグをほかより上に積み、遠い機器のものほど下のフラグにする（遠い配管が近い配管の立ち上がりの下をくぐる。ポンプから3本に分岐して右端のフラグへ、など）
- 配線できないほど混んだ図では、`max_expand` を超えても隙間を広げ続ける（最大4倍）

### 段への折り返し（`"rows": "auto"`、既定）

主流が2つ以上の大きな機器（塔: `column`、または `span` ≥ 2 の機器）を通るとき、図面を横に長く伸ばさず、上から下へ段に折り返す。どこで折り返すかも接続だけから決まる（書き順は使わない）。

- **主流**: 主なフィードから、いちばん長く続く流れをたどった経路（同じ長さなら低いノズルから出るもの＝塔の缶出し）
- **折り返す場所**: 主流が塔を出て次の塔へ向かうところ（塔とその枝のすぐ後ろ。次の段は次の塔へ送る機器から始まる）と、最初の塔の手前（その前に図面端のフラグ以外の機器が3つ以上あるとき。原料の予熱列が1段になる）
- **段をまたぐ配管**: 続き線のフラグの対になる。出る側の段の右端に「to 〈行き先の id〉」、入る側の段の左端に「from 〈出元の id〉」。配管に載ったインライン機器は入る側の段に置く。インライン機器にしかつながらない機器（インライン弁の調節計など）は、その配管と同じ段
- 各段は別々に配置・配線して、左端をそろえて上から積む（段の間には仕様欄の分の余白）。機器の仕様欄は段ごとに、その段の上（回転機は下）に並ぶ
- `Diagram.rows` に各段の上下の範囲（y）が入る。1段のときは空
- 折り返さないときは `"rows": "single"`（Python では `fs.rows = "single"`）。`order` レイアウトでは折り返さない
- 例: `btx_fractionation.json` は 予熱（〜予熱器 E-201）／ベンゼン塔 T-210 とその枝（コンデンサー・還流槽・還流ポンプ・リボイラー）／トルエン塔への送り（缶出しポンプ P-212）とトルエン塔 T-220／キシレン塔への送り（P-222）とキシレン塔 T-230・重質分クーラーの4段。1段のとき（交差17・幅208）より交差15・幅79（警告0）

### 枝ごとにまとめる配置

`flow` レイアウトは段（level）ごとに左から詰めるので、塔のサイドストリッパーや還流槽のように上の段にある機器は、下の段でポンプや冷却器が右へ押し出されても左に残り、同じ枝の機器が離れて縦の長い配管が多くの配管を横切ることがある。3本以上の枝を出す機器があるシートでは、次の2通りで配置・配線して、コスト（Uターン、曲がり＋交差、図面サイズ）の小さいほうを採る（段に折り返したときは段ごとに選ぶ）。

- 自由に詰める（これまでどおり）
- 並び順を守って詰める: 各機器の左端が並び順で前の機器より左に来ない。段をまたいで上下に重なるのはよいので、枝ごとに縦の帯にまとまる。例外は自動主管の切り込み点（主管が必要とする位置）と、リサイクル配管に載ったインライン機器（並び順から外し、送り元の配管のすぐ手前まで寄せる。還流ポンプの吐出の分岐の真上を還流の調節弁がふさがない）

例: `btx_fractionation.json` のキシレン塔の段（4段目）は、並び順を守るほうが選ばれ、その段の交差が 8 → 4（幅は 56 → 81）。ほかの段と `solvent_recovery.json` などは自由に詰めるほうが選ばれる

### 基本の規則

```jsonc
{ "elements": [ {"id": "P-101", "type": "pump", "level": 0}, {"id": "T-101", "type": "column", "level": 1}, ... ],
  "connections": [ ..., {"from": "P-102.out", "to": "T-101.e16", "recycle": true} ] }
```

- `level` は省略できる（「段の自動決定」）。書いた機器はその段に固定。段の中の高さは自動（`elevation` を書けば優先）
- **メインフローは左から右**。ただしポートの向きが優先: 西向きのポートから出る線・東向きのポートに入る線は右から左へ流れる（右端から来るユーティリティ、反転した弁など）
- **還流・リサイクル**は `"recycle": true`。書かなくてもループは自動で見つけ、上流へ戻る線を戻り扱いにする（書けばどれが戻りかを指定できる）
- 段が違う機器は**横位置を共有できる**（ドラムの真下にポンプ、塔の真上にコンデンサー）。ただし流れの線が左に戻ることはない
- 計器・調節計は、つながる機器のすぐ横（線が出る側）に置く
- 図面端のフラグは、接続ポートの向きで左端/右端が決まる
- **ユーティリティ**（冷却水・スチーム・窒素など）は `utility` エレメント（丸の中に `STM`・`N2` などの略号）から線種 `"type": "utility"` の線で入れる（`utility` エレメントから出る線は `type` を省略してもこの線種）。メインフローの並びには影響せず、丸・弁は**使う機器のすぐ横**に置かれる（図面端まで引き回さない。丸は図面端には置かれない。丸には `lead` セル（既定 4）の引き出し線が付くので、計器の丸のように機器に貼り付かない）。戻り（ドレン・冷却水戻り）は `connector` のフラグへ出し、そのフラグもすぐ横に置かれる。フラグごとに `"local": true / false` で強制もできる（`order` モードでも `local: true` なら配置順の位置に置く）
- 上部/下部ノズルへの L 字配管が通るよう、必要な機器を自動で持ち上げる（ユーザーが `elevation` を書いた機器は動かさない）。相手が塔のような背の高い機器（`span` ≥ 2）のときは、塔を持ち上げずに容器のほうを下げる（サイドストリッパーの塔頂から塔へ戻る蒸気。段の床より下へは下げない）
- 機器の東面のポートとほかの機器の上部/下部ノズルをつなぐときは、ノズルを東面から2セル以上離す（面から1セル出て曲がる分。1セルだとUターンになる）
- **直管の長さが足りないときは機器をずらす**: どの配管もポートから1セル以上まっすぐ出て、1セル以上まっすぐ入る。2つのポートが近すぎてこの分が取れないと、L字・クランクでは届かず U字（逆戻り）になる（主管から下へ出た枝管が、主管より上にある塔の入口へ戻る、など）。配線のあと、両端のポートの位置と向きだけでこれを判定し（障害物のない格子で、逆戻りしない経路があるかを探す）、足りないセル数だけ機器をずらして配置・配線し直す
  - 横: 並び順で後ろにある側の機器の手前の隙間を広げる（それより右の機器も一緒にずれる）
  - 縦: 行き先を下げる（上げる）か、出元を上げる（下げる）。段の中での高さを変えるので、段が高くなればその上の段も上へずれる。主管の切り込み点（tee）は同じ主管の切り込み点をまとめて動かし、主管はまっすぐのまま。ユーザーが `elevation` を書いた機器は動かさない
  - Uターンが減り、かつ「(折れ＋交差) × `bend_cost` ＋ 配管長」が増えないときだけ採る（U字を消す代わりに交差が増えるなら、U字のまま）。1本ずつ、最大8回
  - 障害物を避ける U字、逆向きのポートどうしを結ぶアーチ（上へ出て下へ入る）、流れに逆らって戻るリサイクルは対象外
- **ノズルどうしをまっすぐつなぐ配管は2セル以上**: 容器・塔・熱交換器などのノズル（フランジの印を描くポート）どうしを向かい合わせで直結する工程の配管は、長さを2セル以上にする。1セルだと両端のフランジの印と矢印が重なるため（直列の熱交換器、ドラムの真上のドラムなど）
  - 横に向かい合うとき: 機器の間を2セル空ける（ノズルのない機器・弁・ポンプなどとの間は、これまでどおり1セルでよい）
  - 下の機器の頂部ノズルから上の段の機器の底のノズルへまっすぐ上がるとき: 1セルしか離れない配置は配線できないものとして扱い、段の間を広げた配置を使う（そうならない配置には影響しないので、段の自動決定の結果も変わらない）。同じ段の中で上下に重ねたとき（`elevation` を書いたときなど）は対象外
- 下部ノズルのすぐ下（1セル下）に、同じ段のフラグの配管が来るとき（熱交換器の下に冷却水の供給フラグ）は、L字に2セル要るので、フラグを1セル下げるか（段の床なら）機器を上げる。これで別の配管の通り道がふさがることもあるので、そういう図では、動かした場合と動かさない場合の両方で配置・配線し、コストの小さいほうを採る（並び順を守る配置の選択と組み合わせて最大4通り）

### 段の自動決定（`level` を省略）

`level` を書かない機器の段は、図の出来ばえだけで決める（`levels.py`）。機器の役割や配管の流体は推測しない。

- **ポンプは地上**: `pump` は段0に固定
- **それ以外**: 配管の折れ・交差・長さが最小になる段を探す。コストは `(折れ＋交差) × bend_cost ＋ 配管の総長（セル）`
- **探索**: ポンプは段0、それ以外は段1（ポンプのない図では段0）から始め、1手ずつ段を ±1 する局所探索
  - 1手で動かすのは「1機器」「1機器＋その機器にしかつながらないもの（フラグ・計器など）」「1本の配管の両端の2機器」のいずれか
  - 同じ構成の繰り返し系列（並列系列）は、対応する機器をいつも一緒に動かす（系列どうしの見た目がそろう）
  - 候補はまず配線せずに見積もる: 配置だけ行い（約1ミリ秒）、配管ごとに両端のポートの向きから最低限必要な折れ数と、ポート間の距離を足す（交差は見積もらない）。見積もりの良い順に並べ、上位32手だけを実際に配線して確かめる
  - 実際の配線は16手ずつ評価し（並列で計算）、コストが下がる手があればその中の最良を採って次へ。上位32手に下がる手がないか、100手で終わる
  - 1手の評価は、通常の配置（隙間を詰めない、並び順を守る配置やフラグを動かす配置は試さない）で隙間を3通りまで広げて配線したときのコスト。3通りで通らない段の組み合わせは採らない
  - 配線する前に、その手のコストの下限を出す: 3通りの隙間それぞれで配置だけ行い、配管ごとに必ず必要な折れ数とポート間の距離を足した最小値（交差は0とみなす）。どう配線してもこれより安くはならないので、下限が今のコスト以上の手は配線せずに見送る。今より安い手しか採らないので、結果は変わらない
  - 探索のあと、決まった段で通常どおり配置・配線する（隙間の詰め、配置の選択、ポートの入れ替え）
- **書いた `level` は固定**: 探索では動かさない。ポンプに `level` を書けばそれが優先
- 段に折り返す図は、段（行）ごとに探索する
- 結果は `elements` / `connections` の書き順にも、並列で計算するプロセス数にも依存しない。省略した `level` は `to_dict` / `to_json` でも省略のまま
- **時間**: 1手の評価に配置・配線1回分かかるので、`level` を省略した機器が多い図ほど時間がかかる（下の表）。急ぐときや、結果を固定したいときは `level` を書く

作例はどれも `level` を書いていない（段はすべて探索で決まる）。図全体の構築にかかる時間（段の探索を含む）:

| ファイル | 機器（`elements`） | 1プロセス | 4コア |
|---|---|---|---|
| `feed_heating` | 7 | 約0.2秒 | 約0.2秒 |
| `loading_station` | 12 | 約1.4秒 | 約0.8秒 |
| `cooling_water` | 10 | 約2.5秒 | 約1.1秒 |
| `solvent_recovery` | 24 | 約9秒 | 約3.7秒 |
| `btx_fractionation` | 46（4段に折り返し） | 約10秒 | 約4.7秒 |

作例の一覧と結果は [README の作例](../README.md#作例) を参照。

### Uターンの警告

Uターン（いったん進んだ向きと逆へ戻る配管）は、機器を迂回するためなら問題なしとして警告しない（`Diagram.uturns` に本数だけ数え、配置はできるだけ少なくなるよう選ぶ）。何もないところでのUターンだけを「U-turn with nothing in the way」として警告する。判定は、Uの2本の脚の間（つなぐ辺から長いほうの脚の端まで）に機器が重なるか、脚の間に収まる機器が接しているか。ポートの向きと段で避けられないUターンも警告しない（`uturns` には数える）: 下向きのポートから上の段の機器へ、上向きのポートから下の段の機器へ、上の段から下向きのポート（底のノズル）へ、下の段から上向きのポート（頂部のノズル）へ、のどれか。どう配置しても線はいったん逆へ出るので（180° 回したポンプの吐出から上の段のフラグへ、など）。同じ段どうしは配置で避けられることがあるので、これまでどおり判定する。自動で入る分岐点（2×2）はすぐ隣のノズルをふさぐので、同じ面のノズルは2グリッド以上離す。

## ノズル・枝管の自動割り当て

同じ面に並ぶノズルや枝管のうち、役割が同じものは**どれを使っても同じ**とみなし、交差が少なくなるように線の割り当てを自動で入れ替える。接続に書いたポート名は「どの面を使うか」の指定として扱う（`"T-101.n1"` と書いても、頂部の別のノズルになることがある）。

- 入れ替えの対象（エレメントの `Geometry.swappable`）: 縦型ドラム・塔の上下の鏡板のノズル（`n<i>` / `s<i>`、`top` / `bottom` を含む）、横型ドラムの上面・下面のノズル、ヘッダーの枝管 `b<i>`（`branch_elements` で機器が載った枝管は除く）と `m<i>`
- 対象外: 縦型ドラム・塔の胴の側面のノズル（`w<i>` / `e<i>`。高さに意味があるため：段の位置・還流の入口など）、ほかの機器のポート、複数の配管が共有するポート
- 方法: いったん配置・配線した結果で、各ノズルから出た線が最初に曲がる向き（面に沿ってどちらへ向かうか）を見て、面の上で左から右（下から上）に並べ直す。外側へ向かう線ほど外側のノズルを使い、同じ側へ向かう線どうしは面の近くで曲がる線ほど外側になるので、ノズルの手前で交差しない。並べ直して配置・配線をやり直し、コスト（Uターン、曲がり＋交差、図面サイズ）が増えなければ採用する（最大 `SWAP_ROUNDS` 回）
- 使うノズルの組（どの位置のノズルが使われるか）は書いたとおりで、その中で線の割り当てだけを入れ替える
- `Flowsheet` の接続そのものは書き換えない。実際に使ったポートは `Diagram.routes` の接続に入っている
- 繰り返し構成では各系列が同じ配置になるので、割り当ても全系列で同じになる
- 例: `examples/solvent_recovery.json` では、塔の底の2つのノズル（リボイラーへ・缶出しポンプへ）の割り当てが入れ替わり、曲がりが 31 → 29 になる。`btx_fractionation.json` では交差が 16 → 15

## 繰り返し構成の対称化

同じ構成の系列（並列のポンプ系列、複数の塔とその付帯設備など）は、**同じ形に描く**と1系列を読めば残りを読まなくて済む。設定は不要で、自動で次のように扱う（`symmetry.py`）。

- **系列の検出**: 図面端のフラグと自動主管の tee を除いたときにつながっている機器のまとまりを1系列とみなす（配管がフラグや主管にしかつながっていない塔1基でも1系列になる）。左から順に、機器の種類・パラメータ・高さ、系列内の配管（ポート・線種・リサイクル）、外へ出る配管が一致すれば同等な系列
- **配置**: 同等な系列の対応する機器どうしは隙間を一緒に詰める。各系列は最初の系列をそのまま横にずらした形になる。ノズルへの配管のために機器を持ち上げるときも、対応する機器は同じ高さにそろえる（各塔のボトムが図面端に積まれたフラグへ行く場合も、塔の高さはそろう）
- **並び順**: 1つのフィードから分かれた系列が1か所（共通のフラグなど）へ合流するとき、合流先は最後の系列が並ぶまで待つので、系列は id の順（flow）に1系列ずつまとまって並ぶ（合流先が他の系列の機器を手前に引き込まない）
- **配線**: 対応する配管は1本ずつ別々に探索せず、どの系列でも空いている経路を1回だけ探し、全系列に同じ形で敷く（どれかの系列でふさがる経路は選ばない）。共通の形が見つからないときだけ個別に探索する
- **共通設備への合流**: 同等な系列から同じポートに集まる配管は、どれも主管に同じ形で切り込む（最後の1本も主管の端に横から入らず、エルボの tee に同じ向きで入る）。共通主管を系列より上の段に置けば（例: フラグに `"level": 2`）、各系列からは真上に立ち上げるだけでよい
- **主管の切り込み点の位置**: 同等な配管が集まる主管では、並び順は主管がないものとして（ポートから各機器へ直接つながるとして）決め、各切り込み点はつながる機器のすぐ後ろ（機器の西面のノズルへ行くときはすぐ手前）に置く。基準にするのは切り込み点の枝（上下の腕）につながる機器で、主管がそのまままっすぐ入る端の機器ではない（共通のフラグから並列のポンプ2台へ、のように最後の1本が主管の端に入るときも、手前の切り込み点はその枝のポンプの前に立つ）。上流の1つのフラグから各系列へ分配する供給主管でも、系列は id の順（flow）に並び、切り込み点が各機器のノズルの真上（真横）に来るので、主管から機器へはまっすぐ入る

## インライン機器と自動分岐

弁や流量計のように「配管の上に載る」機器は、配置順に並べる代わりに接続に書ける。

```python
fs.connect(
    "P1.out",
    "C1.w8",
    inline=[
        "valve",  # id 省略: タグなし
        {"type": "valve", "id": "FV-1", "params": {"kind": "control"}},
        "valve",
    ],
)
fs.connect(
    "FIC-1.e", "FV-1.signal", kind="signal"
)  # インライン機器の id も接続先にできる
```

- 配置: 行き先 (`dst`) のすぐ手前（行き先が図面端のフラグなら出発元のすぐ後ろ）に、その機器と同じレベルで一直線に並ぶ。`"anchor": "src" | "dst"` で変更可。個々に `level` / `elevation` も指定可
- 右から左へ流れる配管では自動で左右反転（`params` に `mirror` を書けば優先）
- ポート名が `in`/`out` でない機器は `{"type": "instrument", "in": "w", "out": "e"}`
- **自動主管（合流・分岐）**: 1つのポートを複数の配管で共有すると、設定しなくてもそのポートから主管が一直線に延び、各配管は主管に**順番に切り込む**（1点にまとめて集めない）。本数の上限はない。まっすぐ続く配管が主管の端に入り（同じ種類の機器の同じポートから来る配管ばかりで、どれもまっすぐ続かないときは、全部が同じ形で切り込む）、ほかの配管は相手の機器が近い順にポート側から切り込むので配管が交差しにくい。図面端に積まれるフラグから来る（へ行く）配管は、同じ形でも並列系列とはみなさない（切り込み点はフラグの積み順ではなく主管の順に並ぶ。フラグ3本から1つのノズルへの合流も配線できる）。切り込み点は1本ごとに生成される tee（id は `_T_<機器>_<ポート>`, `_T_<機器>_<ポート>_2` …）で、主管の高さはそろえて動かす。生成された機器の id は `_` で始まり、タグは描かれない（`_` で始まる id はユーザーは使えない）
- 配管の合流・分岐点に黒丸は描かない
- 作例: `examples/loading_station.json`（製品受入のフラグから3基のタンクへ分配する主管、N2 の丸からの主管、3台のフィルターから出荷フラグへ合流する主管）、`examples/solvent_recovery.json`（還流ポンプの吐出を還流と留出に分ける主管）

### 自動主管と塔

塔のまわりの自動主管は次のように描く（`tests/test_column_headers.py` に6パターン）。

- **切り込みの向き**: 主管と同じ段の機器から来る配管は、相手のポートの向きで切り込む側を決める。上向きのポート（ポンプの吐出、鏡板の上部ノズル）が主管より低ければ下から、下向きのポート（塔の底）が主管より高ければ上から入る。主管より高い塔頂から来る配管などはこれまでどおり主管の横から入る
- **主管の段**: 上部ノズル（下部ノズル）から出る主管は、配管が上（下）の段へ向かうときだけ上（下）の段に置く。どの配管も逆側へ向かうとき（ポンプの吐出から還流を下の塔へ戻し、留出はフラグへ送る）は、ポートと同じ段でポートのすぐ上（下）に置くので、立ち上がりはポートの真上の tee にまっすぐ入る
- **切り込み点の位置**: 機器の西面のノズル（塔の側面のフィード口など）へ行く配管の切り込み点はその機器のすぐ手前に置くので、主管から下りてそのままノズルへ入る（L字）。それ以外はつながる機器のすぐ後ろ。主管がその先へ続き、手前に切り込み点のある容器の下を通るときは、容器は主管の上に立つ（下の「主管をまたぐ塔」）ので、切り込み点からは上へ出てノズルへ入る（同じ段のポンプから2基の塔の側面へ送る、など）
- **主管をまたぐ塔**: 同じ段で主管の切り込み点のあいだに立つ容器（ポンプの吐出が合流するボトム主管の上の塔など）は、主管の1セル上まで持ち上げる。主管はまっすぐ通り、塔の底からの配管は主管を横切って下のポンプへ下りる
- **図面端のフラグ**: `flow` レイアウトでは、図面端に置かれるフラグは書いた位置によらず、その端の側でいちばん遠い相手として切り込みの順番を決める（主管の端に入り、ほかの配管と交差しない）
- 作例: `examples/btx_fractionation.json`（各塔の還流ポンプの吐出が還流と製品に分かれる主管）
