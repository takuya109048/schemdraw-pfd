# 内部構成と性能

[README](../README.md) から分けた、コードを読む・直す人向けの資料。

## 構成 (`src/schemdraw_pfd/`)

| ファイル | 役割 |
|---|---|
| `geometry.py` | 外周形状（折れ線/楕円弧）とレイキャストによる外周上の接点計算 |
| `elements/` | エレメント定義。**1エレメント＝1ファイル**（`pump.py`, `valve.py`, `vertical_drum.py`, `column.py`, `horizontal_drum.py`, `heat_exchanger.py`, `filter_housing.py`, `header.py`, `tee.py`, `connector.py`, `instrument.py`, `custom.py`）。共通部分（`Geometry`・基底クラス・回転/反転・`ElementLibrary`）は `base.py`、標準エレメントの登録は `__init__.py` の `STANDARD_ELEMENTS`。追加するときは `elements/<名前>.py` を作って `STANDARD_ELEMENTS` に足す |
| `style.py` | `LineStyle`（線の種類ごとの見た目）と `Theme`（フォント・線幅・余白・枠など図面全体の見た目）。描画系に依存しない |
| `layout.py` | グリッド配置: レベル(Y)、順序どおりの専用列(X)、接続ポートを考慮した最小X制約 |
| `router.py` | 直交グリッド経路探索: 曲がり回数最優先→距離。接続面に垂直に出入り、U/Iターン禁止（不可避なら緩和モード。何もないところのUターンだけ警告）。同等な系列の対応する配管は全系列で空いている経路を1回探して同じ形で敷く |
| `netlist.py` | ユーザーが記述するデータ: `Equipment` / `Connection` / `InlineItem` |
| `expand.py` | レイアウト前の展開: インライン機器を配置順に挿入、共有ポートに tee を自動生成 |
| `symmetry.py` | 繰り返し構成（同等な系列）の検出。配置の隙間をそろえる組と、同じ形に敷く配管の組を返す |
| `flow.py` | `layout="flow"` の並び決定: 流れのグラフ、ループ（リサイクル）検出、順位付け、計器の取り付け位置 |
| `model.py` | `Flowsheet`（追加・接続・順序変更・JSON 読み書き・バージョン確認）、展開→配置→配線→隙間ごとの圧縮→入れ替え可能なノズル・枝管の割り当て直し |
| `xlsx.py` | Excel 出力: すべて Excel の図形を部品ごとに（直線・円弧・楕円、矢印付きの直線、テキストボックス）、機器・ラインごとにグループ化。DrawingML を直接書く |
| `render.py` | SchemDraw への描画（`Theme` と線種スタイルに従う）、配管交差の上下表現 |

## 設計上の決まり

`flow` レイアウト（JSON の既定）での並びは [layout.md](layout.md) の決まりが優先する。下の「順序」は `order` レイアウト（Python API の既定）の場合。

| 項目 | 内容 |
|---|---|
| ヘッダー | 枝管はすべて+Y、本数 `branches`、基本等間隔 `pitch`。`branch_elements` で枝管上〜分岐先に機器を直列挿入でき、干渉する箇所だけ「占有幅+1」まで間隔と主管長が広がる |
| グリッド | サイズ・位置・配管の折れ点はすべて整数グリッド |
| 順序（`order` レイアウト） | 追加順（`set_order` で変更可）に各機器が専用の列を持つ。レベルが違っても上下に重ならず、順序は入れ替わらない。例外は行き先を示す `connector` だけで、左端・右端の共有列に上下に重ねて並ぶ（順序で最初の機器より前なら左端、それ以外は右端。`edge` で指定も可） |
| レベル | `level=0` が最下段。各段はその段で最も背の高い機器の高さ分の帯。省略すると図の出来ばえで自動（[「段の自動決定」](layout.md#段の自動決定level-を省略)） |
| 高密度 | 隙間の下限まで詰める。高さが揃って向かい合うポートは1グリッドで直結、上下に1グリッド以上離れていて当たり得ない隣同士は隙間0、それ以外は1。配線が通らない場合だけ全体を広げ、その後は隙間を1つずつ「Uターン数と曲がり数が増えない限り」下限まで戻す |
| 機器追加 / 接続点 | `register_element` / JSON。機器ごとの追加ポートは `ports={"名前": ("N", 3)}`。接続点は辺＋オフセットから内側へレイを飛ばした**実外周との交点** |
| ルーティング | 曲がり数最小 → 距離。同一軸を逆向きに進む経路（U/Iターン）は禁止。機器面からは必ず垂直に1グリッド以上直進（I字/L字） |

## 配線探索と性能

- 段に折り返したときの各段の構築と、配置方法の候補（並び順を守る／守らない、フラグを動かす／動かさない）ごとの構築は、別々のプロセスで同時に行う（CPU の数まで）。どの候補を採るかは順番に作ったときと同じで、結果は変わらない。`Flowsheet.jobs`（CLI は `-j/--jobs`）でプロセス数を指定でき、`1` なら1つのプロセスで順に作る
- 以下の高速化はどれも、探索の答え（配置・配線・警告）を変えない。小さなテスト例（`tests/cases/`）と作例のスナップショットのほか、作例のビルドから記録した実際の探索（約1.6万回）と、ランダムな盤面（約19万回）で、入れる前と経路が一致することを確かめた
- **長引く探索は、残りの曲がり数で絞る**: 推定値（下の A*）が曲がりを数え足りない探索（迂回や U ターンが要る配管、ふさがれた盤面）は、状態をたくさん調べる。厳密モードの探索が `FLOOD_AFTER = 50` 歩を超えたら（緩和モードの探索は、厳密な経路がなかったときに行うので長引きやすく、最初から）、目的地から逆向きに、全状態について「あと何回曲がれば着けるか」を数える（`Router._bend_levels`。向きごと、厳密モードでは通った向きの組ごとの盤面を、1回の曲がりを1段として広げる）
  - 始点に届かなければ経路はないので、そこで打ち切る（盤面のすべての状態を調べ尽くさずに済む）
  - 届けば、曲がるたびに1段下りる経路を1本たどってコストを出し、以後は「ここまでのコスト ＋ 目的地までの距離 ＋ あと要る曲がり × 曲がりコスト」がそれを超える状態を積まない。そういう状態は最安の経路に乗らない。最安の経路に乗る状態は、同じ順に、同じ前の状態から取り出されるので、見つかる経路は変わらない（同じコストの経路の選び方も含めて）
  - 作例の探索時間は 1/2〜1/3（U ターンの要る緩和モードの探索で約1/3）
- **階段判定**（厳密モード、行きと帰りが逆向きのアーチ以外）: 厳密な経路は通った向きと逆へ戻れないので、始点と終点を角とする長方形の中を、決まった2方向だけに進む階段になる。その長方形のセルだけで階段が通るかを、探索を始める前に調べる（通らなければ探索しない）
- **ビットボード**: 盤面のセルを1つの整数のビットに並べ（`_board`）、「その向きに入れるセル」「曲がれるセル」を整数で持つ。まっすぐ進めるだけ進む操作は、北向きは加算の繰り上がり、ほかの向きは倍々（1, 2, 4 … セル）のシフトで、セルの数ではなく曲がりの回数ぶんの演算で済む（`_straight`）。届くかどうかの判定（`Router._reachable`）は、1状態ずつの塗りつぶしの 1/20〜1/50 の時間
- **どの順でも引けない配管は引き直さない**: 引いた配管は、ほかの配管の通れるセル・曲がれるセルを減らすだけなので、ほかの配管を1本も引いていない盤面でも引けない配管（`Router.routes_alone`）は、どの順に引き直しても引けない。そういう配管があれば、その配置の引き直し（リップアップ＆リルート）はしない。段の自動決定の評価では、その場で配線をやめる
- **作り直さない**: 機器の形（Geometry）は、構築の間、種類・パラメータ・ポートが同じなら1つを使い回す。ポートの位置（外形に当たる点）は形ごとに、接続の両端（`id.port` の分割）は接続ごとに覚える。入力の検査は構築ごとに1回。段の自動決定では、同じ段の組み合わせを2度評価しない（手を戻したときなど。超えるべきコストは下がる一方なので、前の答えがそのまま使える）
- これらを入れたことで、当時の作例のビルドは 1プロセスで 1/4〜1/14、テスト全体は 約5分 → 約1分 になった
- 今の作例のビルド時間（段の探索を含む）: `feed_heating` 約0.2秒、`loading_station` 約1.4秒（4コアで約0.8秒）、`cooling_water` 約2.5秒（約1.1秒）、`solvent_recovery` 約9秒（約3.7秒）、`btx_fractionation` 約10秒（約4.7秒）。テスト全体は4コアで約1分20秒

- 経路探索は A*。推定値は「マンハッタン距離 ＋ 今後どうしても必要な曲がり数 × 曲がりコスト」で、過大評価せず一貫性もある（テストで確認）ので、結果は従来の Dijkstra と同じ最適経路（ランダムな297図面で経路が完全一致）
- **リップアップ＆リルート**: 配管は1本ずつ順に引くため、先に引いた配管が後の配管の唯一の通り道をふさぐことがある。失敗した／Uターンが必要になった配管があると、全部はがしてその配管を先頭にして引き直す（最大 `REROUTE_ROUNDS = 3` 回）。結果の `Diagram.routes` は常に接続の定義順
- 厳密モードで配線できないときは、間隔を広げた候補をすべて試し「Uターン数 → 曲がり数」が最小のものを選ぶ
- 圧縮: 同じ配置になる隙間変更は再配線しない（キャッシュ）。試行中の配線が現在のベストより悪くなった時点で打ち切る
- 段を書いた図は段の探索を省けるので速い（段の探索は1手ごとに配置・配線1回分かかる。[layout.md](layout.md#段の自動決定level-を省略)）
